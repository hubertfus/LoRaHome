main loop.*

it, read a BME680 and a debounced digital input without ever blocking, and

## Three findings worth carrying forward

**Bosch's integer compensation overflows twice, and both are silent.** Sweeping
each BME680 channel across its whole raw domain — rather than across a window a
reasonable person would pick — found humidity wrapping from a clamped 100% to
exactly 0% at raw count 54032, and pressure stepping 1954 Pa *upwards* in a
curve that only falls, near 106 kPa. Neither crashes. Both produce numbers a
rule engine would act on. A healthy sensor never reaches either point; a
corrupted I2C read reaches the first immediately. Both are computed in 64 bits
here, which agrees with the reference wherever the reference is valid and keeps
working where it wraps.

**Two asymmetries in the driver fault accounting were wrong the obvious way.**
A successful `start_read` cleared the error count, which made the fault
threshold unreachable for exactly the component it exists for: a permanently
stuck sensor accepts `start_read` every cycle and reset its own count one call
before timing out again. And a hard error left the context in `READING`, so the
next `start_read` was refused as "already measuring" — a component that hit one
bus error went silent with no counter saying so. Both have regression tests
naming the symptom, because the observable behaviour of each is a sensor that
has quietly stopped reporting.

**The capability wire budget was worked out wrong and the test caught it.** 93 B
assumed bus type, channel count and flags would stay in CBOR's inline form. They
do in every report the system generates and they do not in every report it can
be *sent*, so the reachable maximum is 109 B. The bound a receive buffer needs
is the reachable one.

**Three of ten need hardware.** They are the same three the stage could never
have closed without a board: real readings, the receive-window interaction, and
the current draw that feeds the Etap 7 energy calculator. Every one is reported
`SKIPPED` with its budget still attached rather than dropped, so attaching a
board turns them into numbers without anybody having to remember they were
missing.

## Known environment issue

This machine's Application Control intermittently refuses to execute
just-linked unsigned binaries, which blocks a different Unity suite on most
runs. Every suite passes when it launches, and the full set is 80 cases. Three
fixes were attempted and each was disproven by measurement — rebuilding (four
consecutive invocations all blocked), a fresh path (copies refused too), and a
longer backoff (ten seconds, no improvement) — while the same binary runs fine
from any directory a minute later. None of that work is in the repository. The
remedy is a Defender or Application Control exclusion for the build tree, which
is a machine setting rather than a code change.
